lantas docs · 1.0 · free

The whole desk, in one window

Lantas is a free macOS agent: a chat, a code workspace and a browser that can read and act. Ask a question, change a repo, connect the apps you work in, or hand it the tab you have open. Everything runs on your Mac with the model you choose.

getting started

Installation

Lantas is a macOS app. Download the dmg for Apple silicon from the releases page, open it, and drag Lantas.app to Applications. You need macOS 11 or newer, and Chrome 116 or newer for the extension.

$open ~/Downloads/Lantas-1.1.3-arm64.dmg

Or take Lantas-1.1.3-arm64.app.zip and unzip it into Applications. The Chrome extension is inside the app at Contents/Resources/chrome-extension, and the app shows you the folder.

Nothing is built on your machine, and no toolchain is needed.

The build is ad-hoc signed, so macOS asks you to approve Lantas once. Open System Settings → Privacy & Security, click Open Anyway, then authenticate. After that it opens normally. The installer clears the flag for you if you prefer.

Start it

$open -a Lantas

There is also Lantas.command in the repo, for the web build while you are working on the UI. It is not the app.

getting started

First run

Lantas opens on the chat. Three things to do once:

  1. Open Settings → Providers, pick Anthropic, OpenAI, OpenRouter, Groq, Google or NVIDIA NIM and paste a key — or point it at Ollama or LM Studio, which need none.
  2. Pick the model the agent should use. The model list is fetched from the provider when a key is present.
  3. Open Browser, then Chrome extension, and load the extension folder Chrome is told about.

Keys live in the app's own storage on your Mac. They are not synced, not proxied through a server, and never committed anywhere.

Without a provider the app still opens and the browser still works. The agent will say it needs a key rather than answer.

getting started

Quickstart

Four steps, and the first task takes about a minute.

  1. Download the dmg, drag the app to Applications, and open it.
  2. Load the extension once: chrome://extensions → Developer mode → Load unpacked → the folder the app shows you.
  3. Open the page you care about in Chrome, then click the Lantas icon. The side panel opens on the right.
  4. Ask. “Summarise this page”, “find the invoice and download it”, “click Place order”.

The app has to be open: the panel talks to it over a loopback socket on 127.0.0.1:47654. If the app is closed the panel says so instead of pretending.

getting started

The Lantas window

Three tabs, one window, and a side panel that can sit in any of them.

chat
Threads with the agent, slash commands, file and image attachments, and screen sharing
code
A workspace folder, files in the tree, edits as diffs, and the GitHub panel
browser
Lantas' own webview, or your real Chrome through the extension. A home page with bookmarks, history and a star beside the address bar.
the rail
Ask about the page you are on without leaving it. The switch at the bottom is whether the agent may act.
modes
Build writes, Plan drafts, Chat answers — chosen per thread

Colour has one job in the browser: the accent marks what is live or selected, red marks a failure, and everything else is grey.

everyday

Chat

A thread per topic. The agent keeps the thread's context, and you can rewind a turn, compact a long thread, or export it as JSON. Every session is listed in the sidebar and searchable from ⌘K.

Three modes

chat
Answers without touching anything. Read-only.
plan
Reads the repo and drafts an approach before a file changes. Read-only.
build
Reads, edits and runs commands in the folder you opened.

The mode sits in the composer and is chosen per thread: Plan for the shape of a change, Build when you want it written, Chat when the answer is the whole point.

Attachments and the screen

Drop files or images into the composer, or pick them with /attach. /screen asks for a window or a display, samples it at four frames a second, and attaches one frame to the question. The stream stays in this process; it is never uploaded.

Slash commands

Type / for the menu, or reach the same commands from ⌘K.

/new · /clearStart a fresh thread, or empty this one
/code · /chatMove between the workspace and the thread
/attach · /screenAdd files, or share a window or display
/initScan the repository and write an AGENTS.md
/review · /diffReview the working tree, or walk the last change
/fix · /testReproduce a failure and fix the cause
/commitCommit the working tree
/plan · /buildSwitch the mode without opening a menu
/model · /usageChoose a model, or read tokens and context
/skills · /mcpManage skills and MCP servers
/undo · /redoRewind a turn, or put it back
/compact · /exportSummarise the thread, or download it

Settings → Commands adds your own: a name, a description, and a prompt body that receives $ARGUMENTS. Custom commands and skills appear in the same menu as the built-ins.

everyday

Code

The Code tab is a workspace: a folder you pick with the native dialog, or files you drop on the panel, up to 600 of them. Lantas reads every text file under it, skipping node_modules, .git, dist, build, target and similar, then shows the tree with a filter.

Inside the workspace you get VS Code's Monaco editor, tabs, quick open (⌘P), project-wide search and an assistant dock beside the file. A terminal panel runs commands in the same folder, and the workspace bar shows the branch and changed files. Add more than one folder when a project spans repositories; the tree, search and git context follow all of them.

Nothing is uploaded. In the desktop build the folder is read through Tauri's filesystem plugin; in a browser tab it uses the File System Access API with the permission you grant.

Edits are diffs

An edit arrives as a diff: the file, the lines and the reason. In Code mode the assistant stages its writes, and the review bar lets you Keep or Discard each file, or all of them. A save is read back from disk, so a write that did not land is reported as a failure. Build mode may propose changes; Plan and Chat only read.

everyday

Workspace and apps

Integrations come in two kinds: managed toolkits through Composio, and MCP servers you add yourself. Both make the services you already use callable from the same thread.

Composio

Add a Composio project key once in Settings → Integrations. From that panel you connect an app, finish the sign-in in your browser, and the toolkit appears in the list as active. Each connection can be revoked from the same place.

communication
Gmail, Slack, Discord, Telegram, WhatsApp, Outlook, Intercom, Zendesk
productivity
Notion, Calendar, Drive, Airtable, Trello, Asana, monday.com, ClickUp, Todoist
developer
GitHub, Linear, Jira, Sentry, Vercel, Supabase
crm
HubSpot, Salesforce, Pipedrive
storage · social
Dropbox, Box · X, Reddit, YouTube, Spotify

Thirty-two in all. The key and the connection tokens stay in this app's storage on your Mac; the browser tab only does the sign-in step.

Gmail, directly

The Google panel is the other route: a read-only Gmail inbox through your own OAuth client. Nothing is written back, the token stays local, and disconnecting clears it.

MCP

Settings → Integrations adds Model Context Protocol servers. An HTTP server gets a real initialize handshake from Test; a stdio server keeps its command and starts with the desktop runtime. A filesystem, a database, your own service — anything with an MCP server becomes a tool the agent can call.

everyday

Skills and commands

A skill is a paragraph of instructions appended to the system prompt while it is switched on. Thirteen ship built in, covering commits, review, debugging, test gaps, refactors, release notes, PR descriptions, API design, SQL, security and interface copy. The four you will reach for most:

commit
A conventional commit message written from the staged diff
review
A diff read for correctness, edge cases and regressions
release notes
A changelog entry from the commits since the last tag
test gaps
The cases a change leaves untested, and the smallest test that would catch them

Write your own in Settings → Skills: a name, a description and the instructions. Enable it for a thread and it joins the prompt; leave it off and it costs nothing.

Commands are the other direction — a name you type and a prompt body. Both live in Settings, and both appear in the composer's slash menu next to the built-ins.

the browser

Two engines

The browser tab has a switch with two positions.

lantas
A native webview inside the app. Pages render in Lantas, links stay in Lantas, and the agent reads them through the app.
chrome
Your real Chrome. Lantas sends commands to the extension and the extension acts in the tab you have open, with your logins and your extensions.

Use the Lantas engine for reading and research; use Chrome for anything that needs you signed in. The engine is remembered between launches, and the browser always opens on its home page.

Some sites refuse to load in a webview at all — Notion, Google Docs, most banks. That is what the Chrome engine is for.

the browser

The Chrome extension

A side panel, not a popup. Click the Lantas icon in the toolbar and the panel opens on the right of the tab you are reading.

Load it once. The app shows the folder, or use this path:

$/Applications/Lantas.app/Contents/Resources/chrome-extension

What the panel shows

status
Connected or not, and the app it is talking to
the page
Title, address and how many controls the agent can see
the thread
Your questions, its answers, and a note for every action it ran
let lantas act
The kill switch. Off means read-only, immediately

How it talks to the app

The extension opens a WebSocket to ws://127.0.0.1:47654 and says hello. The app only accepts chrome-extension:// origins, so a website cannot pretend to be the extension. Commands go one way, results and answers come back with the same id.

Reloading the extension gives it a new id and breaks the connection until Chrome reconnects. Keep the folder in one place.

The extension asks for Chrome’s debugger permission so its clicks and keystrokes go through the browser’s real input pipeline, not a JavaScript imitation. Chrome shows a “Lantas started debugging this browser” banner while an action runs. Close DevTools on that tab if Chrome refuses to attach; Lantas falls back to DOM actions automatically.

the browser

Reading the page

The content script returns four things, and nothing else:

title · url
What the tab says it is, with query strings and fragments intact
text
Visible text, cleaned of scripts and styles, capped so one long page cannot eat the context
controls
Buttons, links, inputs, selects and textareas: role, accessible name, value, whether visible and enabled
elements
A short numbered list of the labelled controls, so the model can name one instead of guessing coordinates

Nothing is captured as an image. There is no OCR, no screenshot, and no cursor tracking. A page the extension cannot script — chrome://, the Web Store, PDF viewers — is reported as unreadable rather than half-read.

Iframes on another origin, closed shadow roots and canvas-only apps are read as text at best. Lantas says which part it could not see.

the browser

Acting on the page

Seven actions, one at a time:

ActionWhat it needs
clickThe label of the control, or a CSS selector as a fallback
typeThe text, and a field by label or selector; optionally submit
enterNothing: Enter goes to the focused field
scrollPixels up or down
openA URL, in the current tab or a new one
back · forwardNothing
reloadNothing

How a click finds its target

By label first. The extension scores the control's accessible name against what the model asked for; a button that moved is still a button. A CSS selector is the fallback, and coordinates are never used. If two controls match equally well, the agent asks instead of picking one.

What it will not do

It does not press anything destructive without the word in your request, does not type into password or payment fields without an explicit ask, and does not click a disabled control. When the switch is off, every action is refused in the extension before it reaches the page.

After every action

The page is read again. If the confirmation the step expected is not there, the action is reported as failed — with what the page actually said — rather than as done. The answer you read in the panel is the step that ran, not a description of it.

OpenAI-compatible
Any base URL: a local server, a gateway, or your own proxy

The default model is yours to choose per session, and the agent switch in the browser rail uses the same provider. Nothing is sent to Lantas: requests go from your Mac to the provider you picked, with the key you pasted.

For NVIDIA NIM, create a key at build.nvidia.com, paste it into Providers, and use Fetch models to fill the picker from that key’s live catalog. The base URL is https://integrate.api.nvidia.com/v1.

A local endpoint needs no key. Set the base URL to http://127.0.0.1:11434/v1 or whatever your server serves, and pick a model name it knows.

models

Why it is free

Lantas is free: no subscription, no seats, no trial, no per-task fee and no account. You download it, it runs on your Mac, and there is no server of ours in the middle of anything.

the app
$0, free to download and use
the model
Yours. A local model on the same Mac costs nothing; a hosted key is billed by that provider, not by us
the machine
0.06 s to read a page of 42 controls, 0.11 s to match locally

There is no metering inside the app, no analytics endpoint and nothing to upgrade. The only number that can move is your provider's bill, and the composer always shows which model is making the call.

Caveats

  • Eleven tasks is a sample, not a study. The tasks were written by us, and we knew what the right answer looked like.

  • The three tools were run on different models because those are the models each is built around.

Overhead

Where a two-step task spends its 2.3 seconds of machine time:

reading the page
0.06 s for 42 controls, through the extension
matching
0.11 s locally, no model
the model
2.1 s, waiting on the provider

The app is a native Tauri binary. Its idle cost is a window and a socket; there is no browser engine running until you open the browser tab, and no polling loop when the panel is closed. The bridge keeps one socket per Chrome profile.

Security

the bridge
Loopback only, and it refuses any origin that is not chrome-extension://
page data
Sent to your provider with the question you asked, and nowhere else
keys
Stored in the app's own storage on your Mac, never in the repo
integrations
Composio and Google tokens stay in this app's storage; an MCP server runs where you point it
telemetry
None. There is no analytics endpoint to turn off
the switch
“Let Lantas act” off means the extension refuses every action

The extension asks for tabs, scripting, storage and sidePanel. It reads a page only when a question or an action needs it; it does not run in the background on every site you visit.

Lantas asks before it acts

On first launch Lantas shows a permission sheet instead of assuming consent. Each capability is a separate grant — files, commands, screen and computer control — and every tool checks its grant before it runs, so a denied capability returns a plain “not allowed” answer instead of reaching your disk, a shell or the screen.

Change any grant in Settings → Permissions, or reopen the sheet with Review permissions. Choosing a folder also counts as consent to read that folder. Screen Recording and Accessibility are granted by macOS itself; the sheet opens the right System Settings pane, but only you can flip the switch.

The exact data flows are on the privacy page; the terms and licence are on the terms page.

Troubleshooting

The app will not open

Open System Settings → Privacy & Security, scroll to Security and click Open Anyway next to Lantas. If the app was copied by a script and still refuses, run xattr -dr com.apple.quarantine /Applications/Lantas.app.

The panel says “Lantas is closed”

The app is not running, or the bridge port is taken. Open Lantas; if it is already open, quit it and start it again. The port is 127.0.0.1:47654.

Chrome will not load the extension

Chrome 116 or newer is required. In chrome://extensions, turn on Developer mode, choose Load unpacked, and pick the chrome-extension folder inside the app bundle. Loading it from a moved folder gives a new id.

It cannot read a page

chrome:// pages, the Chrome Web Store, the PDF viewer and other extensions' pages cannot be scripted. Switch to a normal website tab.

A workspace will not open

In the desktop app the folder picker is native. In a browser tab the File System Access API is only available in Chrome, and it asks for permission once per folder. You can always drop files onto the Code tab instead.

An app will not connect

Composio project keys start with ak_. Finish the sign-in in the browser window the panel opens, then refresh the list; it polls while a connection is pending. The web preview blocks Composio's API because of CORS, so connect from the desktop build.

It clicked the wrong thing

Say which control you meant by its visible words. Matching is by label; if the page has two buttons with the same name, Lantas asks rather than picking one. The side panel shows the label it matched.

A provider call fails

Check the key and the model name in Settings → Providers. A 401 is the key, a 404 is usually the model id, and a timeout is the network. The panel reports the provider's own message rather than a generic error.
