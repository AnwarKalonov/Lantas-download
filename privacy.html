Lantas · legal

Your Mac keeps your data.

Lantas has no account, no analytics and no server of its own. This page lists every moment when something can leave your computer, so you can decide before it does.

Effective 25 November 2026 Applies to the Lantas app, the Chrome extension and this website Questions github.com/AnwarKalonov

The short version

Account
None. There is no sign-up, no login and no user profile on a server.
Telemetry
None. No analytics, no crash reporting, no usage counts, no advertising identifiers.
Our server
There isn't one for your work. Chats, files and settings stay on your Mac.
Model calls
When you send a turn, the request goes straight from your Mac to the model provider you configured, using your key.
Screen
Captured only while you turn screen access on, and only attached to the turn you send.
Deleting
Delete the app's data folder and everything Lantas stored is gone.

What stays on your Mac

Everything Lantas writes is stored locally, in the app's own data folder:

  • Chats and sessions — your threads, messages, plans, todos and checkpoints. On desktop these are checkpointed to ~/Library/Application Support/Lantas/sessions.json after each turn.
  • Settings — the model you picked, the mode, your interface choices and your permission grants.
  • Provider keys — the API keys you add are stored in the app's local settings and used only to call that provider. They are not sent to us, and there is no Lantas key server.
  • Workspace state — the folder you opened, open buffers, changed-file lists and git context read from your own disk.
  • Audit log — a local record of the actions the agent took, kept so you can review them.
  • Screen frames and attachments — held in memory for the turn you sent. A screenshot is part of that request only if you attached it.

In the browser preview of the app, the same information lives in that browser's local storage instead of the Application Support folder.

What leaves your Mac, and when

1. The model you chose

When you send a message, the app sends the conversation, the parts of your workspace the agent read, and any attachment or screen frame you included to the provider you configured — Anthropic, OpenAI, Google, OpenRouter, Groq, or a local server such as Ollama or LM Studio. That request is between you and that provider, under their terms and privacy policy. Lantas does not proxy it and does not keep a copy.

If you run a model locally, no model request leaves the machine at all.

2. Release and update checks

The app asks GitHub for its release feed so it can tell you a newer version exists, and this website reads the same public feed to list versions. That request includes your IP address, as any web request does. It carries no account, identifier or telemetry payload.

3. Apps you connect yourself

Integrations are opt-in. If you connect Gmail through your own OAuth client, add a Composio toolkit, or attach an MCP server, then using that tool sends the relevant request to that service. OAuth tokens are stored locally. Each connected service processes the data under its own policy. You can remove a connection at any time in Settings.

4. The Chrome extension

The extension reads a tab only when you ask Lantas to work with it, and hands the page text, controls and the result of an action back to the app on your Mac. It does not send your browsing history anywhere. It requests Chrome's debugger permission so clicks and keystrokes go through the browser's real input pipeline; Chrome shows its "started debugging this browser" banner while that happens.

5. This website

The site is static. It sets no advertising or analytics cookies. It stores your light/dark choice and a short cache of the release list in your browser's local storage. Fonts are loaded from Google Fonts, so Google receives the request for those files; nothing else on the page contacts a third party.

Permissions are asked, not assumed

On first launch Lantas shows a permission sheet before it uses anything. Each capability is a separate grant, and every tool checks the grant before it runs:

  • Files — read and edit files in the folder you opened. Choosing a folder is treated as consent for that folder.
  • Commands — run builds, tests and git in that folder.
  • Screen — attach a screenshot to a turn while it is on. Turn it off and nothing is captured.
  • Computer control — let the agent click, type and scroll in the browser.

Screen Recording and Accessibility are also granted by macOS itself, in System Settings → Privacy & Security. Lantas can open the right pane for you but cannot flip the switch; only you can. Revoke a grant there, or in Settings → Permissions, and the matching tool stops working immediately.

Retention and deletion

We hold nothing to retain: there is no Lantas account and no server-side copy of your work. On your Mac, data stays until you delete it.

  • One thread — delete it from the sidebar.
  • Everything — quit Lantas, then remove ~/Library/Application Support/Lantas. That deletes sessions, settings, keys and the audit log.
  • Browser preview — clear the site's local storage for that origin.
  • Provider copies — content sent to a model provider is governed by that provider's retention policy. Use a local model if you need the request to stay on the machine.

Security

Lantas is a local application, so the security of your data depends mostly on your Mac: an account password, FileVault and a screen lock are the real protections. Keep provider keys in the app rather than in shared files, and revoke a key at the provider if a machine is lost.

Downloads are covered by the release signature the app verifies before installing an update. The current build is ad-hoc signed rather than notarized, which is why macOS asks you to approve it once.

Children

Lantas is a developer tool and is not directed at children under 13. It does not knowingly collect personal information from anyone, because it does not collect personal information at all.

Changes to this policy

If a future version of Lantas adds a feature that sends data somewhere new, this page will say so before that version ships, and the effective date above will change. The app will keep asking before it uses a new capability.
